# アップデートのお知らせ

iOSアプリのタイトル画面で、インストール版より新しい版が日本のApp Storeに公開されると「アップデートがあります」と表示される。メニュー下の「App Storeで更新」からストアを開ける。起動、タイトルへの復帰、アプリの再表示時に確認し、前面にある間は定期的に再確認する。戦闘中の画面は切り替えない。

拠点の「お知らせ」にも同じバージョンの未読バッジと更新情報を表示する。報酬の操作も引き続き使える。バッジは告知を開くと消える。更新済みの場合は変更点だけが表示される。App Storeで公開版を取得できれば、公式サイトに告知を登録しなくても新バージョンを表示する。公式サイトの告知が公開版と同じ場合はその変更点を表示する。

## 配信の準備

- ブラウザ配信用のCloudflare Pages Functionは `/game/data/app-update-notice.json` で、日本のApp Storeの公開版と変更点を返す。既存の1.0.6・1.0.7の拠点告知もこのURLを使う。
- URLがHTTP 200でJSONを返し、Capacitorの `Origin: https://localhost` のリクエストを許可することを確認する。配信サーバーに接続できない場合は、アプリに同梱した `data/app-update-notice.json` の変更点を表示する。
- 公開後、対象バージョンがApp Storeと告知URLの両方で取得できることを確認する。告知IDには公開版の番号を使い、新バージョンは別の未読告知になる。Appleから取得できない場合はHTTP 503を返す。

例（バージョンと変更内容は実際に公開した版に合わせる）。

```json
{
  "enabled": true,
  "id": "release-1.0.6",
  "version": "1.0.6",
  "title": "アップデートを配信しました",
  "changes": ["拠点の「お知らせ」からアップデート情報を確認できます。"]
}
```

## 審査用ビルドにまとめる前の確認

- 装備・OPの確定差分を同じ検証ビルドに取り込み、ログインボーナスの受け取り、既存セーブからの装備表示、OP表示を確認する。
- 配信前の確認はテスト用の告知を使い、iPhoneで旧版からのApp Store遷移、最新版の変更点表示、通信できない場合の拠点操作を確認する。
- App Storeの「このバージョンの最新情報」には実際に入った装備・OP更新の項目を追加する。審査の提出は別途。
